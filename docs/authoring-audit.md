# Skill authoring audit and repairs

Audit date: 2026-10-04. Scope: 29 independently installed skills across five repositories. The six practices below are contents lists, degrees of freedom, direct reference loading, progress checkpoints, correction and recheck loops, and portability. The starting baseline was five passing validators and 610 passing tests.

The format follows the [Agent Skills specification](https://agentskills.io/specification). The 100-line index boundary is a local authoring gate, not a certification rule from that specification. High freedom applies to explanations, teaching, visual composition, hypotheses, negotiation wording, and candidate generation. Medium freedom applies to procedures, reference entries, reports, maps, and handoff scaffolds. Low freedom applies to facts, literals, arithmetic, proof order, JSON, disclosure boundaries, and review counters. User-required formats and established authorization always take precedence over adaptable scaffolds.

Eighteen references lacked contents lists: ten technical-writing, five business-writing, and three agent references. Five existing long-file indexes also lacked links or subheadings; these were repaired without replacing their explanatory search cues. Fenced examples do not contribute headings or resource reachability. Every runtime reference is linked directly from its entrypoint; nested-only and orphaned references now fail validation.

No descriptions, trigger fixtures, output kinds, target-model UI metadata, or model-calling workflows changed. Required runtime rules are present locally. The existing bounded review loop and ongoing interview retain their own limits and stopping rules. Skills with compliant workflows retain them; `technical-docs-reviewer` and `challenge-me` are unchanged, and `review-loop` changes only its reference index.

Agent and visualization maintenance fixtures, tests, and tooling remain local under their distribution rules. Agent public CI retains a standalone standard-library validator; the other bundles use a repo-local maintenance helper. No skill entrypoint depends on these maintenance tools.

## Evidence and verification keys

Each evidence path is relative to the named repository, with reference paths relative to that skill.

- R: 17 resource regressions in each repository: 100/101-line boundaries, absent or unlinked indexes, missing subheadings, incorrect anchors, duplicate and punctuated anchors, backtick/tilde fences, nested example fences, nested-only/orphaned resources, and standalone containment. Each of the 29 skills is additionally copied alone and its links validated.
- P: real helper execution from relocated folders with spaces in their names, an unrelated working directory, and isolated Python (`-I`); weighted results/ties, exact expected values, and TRIZ asset-backed queries are checked.
- L: source inspection confirms deductive prose routes to deduction, causal/generalizing/analogical prose to induction, and requested deductive symbolization/proof to formalize. Naming uses the relevant fallacy category. This checks authored routing, not model execution.
- F: workflow fixtures updated for final source fidelity, unverified gaps, internal progress tracking, scope control, or advisory execution boundaries. Fixture validation is structural evidence only.
